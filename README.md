# Cid-Larder

Cid-Larder 在本机运行，把 B 站收藏夹按内容主题重新分类：读取账号内的收藏，由对话模型生成分类方案，用向量相似度将每条视频归入相应类别，低置信度条目交由模型复核，确认后才写入账号。数据仅在本机处理，只有视频基本信息会发送至用户配置的模型服务商。

## 前置条件

使用前需准备以下两项：

1. **B 站账号**：通过扫码登录。登录态仅保存在内存中，进程退出即失效，每次启动需重新扫码。
2. **两个模型服务**：
   - **对话模型**：生成分类方案、复核条目、撰写分类说明；
   - **文本向量（Embedding）模型**：计算内容与分类之间的相似度。

   两者可来自同一服务商，也可分别配置。部分服务商（如 DeepSeek）仅提供对话模型，需另行配置向量模型。

本项目不内置模型额度，不提供代理或代付。缺少任一配置时，页面会在启动后自动打开设置对话框；配置完成前，生成分类与归类功能不可用。

## 工作流程

共五个步骤：前四步只读，第五步写入账号。

1. **采集**：读取全部收藏夹及其中的视频，写入内存数据库，不修改线上数据。
2. **生成分类**：将内容格式化为一行文本（标题、UP 主、时长、发布月份、简介前 32 字；按最近收藏排序，单次最多 2000 条）提交对话模型，要求按内容主题分组，并为每组给出名称、一句定义，以及至多 5 个原始标题作为示例。
3. **归类**：为每条内容与每个分类分别计算向量，取余弦相似度最高者。不设绝对阈值：0.3 表示“在当前候选中最为接近”，不代表内容与分类相似。
4. **复核**：将置信度显著低于所属分类中位数的条目提交模型判断，模型可改判至其他分类，或移入「存疑」。
5. **执行**：创建收藏夹（名称未被占用则直接使用；已被占用则创建「名称-AI分类」，若该名称已存在则复用）→ 按每批 20 条移动 → 输出执行结果 → 列出本轮被清空的收藏夹，经确认后删除。

## 安全边界

- **不删除、不重命名、不隐藏任何视频。**
- **仅有一种删除操作**：删除本轮被清空的收藏夹。执行结束后列出清单，需手动确认。
- **不保存登录态**：会话数据仅存在于内存，进程退出后清空；收藏库与归类计划同样不落盘，重启后需重新采集。
- **不提供回滚功能**：每次执行前，工具会从服务端导出一份 JSON（包含容器、条目、成员关系与本轮计划）并触发浏览器下载；导出失败时不会进入确认环节。浏览器是否成功写入磁盘无法由页面确认，请以下载完成为准。数据恢复需依据该文件手动完成。
- **不影响未勾选的收藏夹**：整理页可通过复选框将任意现有收藏夹排除在本次任务之外，其内容不参与分类，也不会被执行移动；该收藏夹的名称仍视为已占用。

## 数据流向

| 数据 | 去向 |
|---|---|
| 标题、UP 主名、时长、分 P 数、发布月份、简介前 32 字、合集名 | 用户配置的对话模型服务商（生成分类、复核、撰写说明） |
| 每条内容生成的向量 | 用户配置的向量模型服务商 |
| Cookie、登录态 | 仅存于本机内存，不落盘、不外发 |
| 收藏夹结构、移动记录 | 仅存于本机内存 |

模型服务商可为任意兼容 OpenAI 接口的端点，对话与向量服务可分别配置。本项目不接入第三方统计或遥测服务。

## 运行要求

- Python 3.11 或更高版本
- Windows / macOS / Linux。Windows 可直接双击 `run.bat`，其他平台使用下方命令

## 安装与启动

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Windows
.venv/bin/pip install -r requirements.txt       # macOS / Linux
python scripts/serve.py
```

启动后服务仅监听 `127.0.0.1`，端口自 8000 起选用首个空闲值，并自动打开浏览器。

## 模型配置

在左侧边栏底部「模型」一栏点击「设置」填写；也可将 `.env.example` 复制为 `.env` 后填写。

页面中填写的配置保存在 `data/config.json`，Key 以明文存放于本机，该目录已被 git 忽略。`.env` 中的同名项优先级更高。可选服务商与注意事项见 [`docs/providers.md`](docs/providers.md)。

## 使用流程

扫码登录 →「开始采集」→「换一换」生成分类（可调整分类数量，也可排除暂不处理的现有收藏夹）→「开始归类」→ 核对清单 →「执行」。

执行前建议核对每个分类的条目数量。分类数量可在 1–50 之间调整，超过 20 个时页面会提示收藏夹列表将相应变长。

## 项目结构

| 路径 | 内容 |
|---|---|
| `app/adapters/` | B 站接口调用与扫码登录 |
| `app/core/` | 采集、生成分类、归类、执行、备份 |
| `app/web/index.html` | 全部界面，单文件 |
| `scripts/` | `serve.py` 启动脚本及只读调试脚本 |

数据库为内存 SQLite。`data/` 存放模型配置与 `scripts/` 调试脚本的日志，已被 git 忽略。

## 已知限制

- **分类建议最多读取 2000 条**：按最近收藏时间排序，超出部分不参与生成分类，但仍会参与归类并计入各分类的条数。
- **分类结果不确定**：同一份数据在不同运行中可能得到 15 个或 18 个分类。滑条设定的数量为目标值，不是保证值。
- **复核仅依据相对水平**：判定标准为“低于所属分类中位数的 75%”，若整个分类的归属均存在偏差，则不会有条目被判定为离群。分类规模越小，越容易出现这种情况。
- **创建记录不持久化**：重启后无法识别上一轮由工具创建的收藏夹，会将其视为用户已有收藏夹，进而创建带「-AI分类」后缀的新收藏夹，原收藏夹清空后出现在待删除列表中。
- **B 站存在访问频率限制**：被拒绝的批次最多重试两次；请求超时不重试，因为此时移动可能已生效，重试存在重复移动的风险。
- **仅支持 B 站**：数据模型中保留 `platform` 字段，但目前仅实现一个平台。
- **界面仅提供中文。**
